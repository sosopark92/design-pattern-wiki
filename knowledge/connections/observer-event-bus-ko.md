# 연결: 옵저버와 이벤트 버스

## 연결 고리

이벤트 버스는 Subject(발행자) 역할을 공유된 중앙 중개자로 추출한 옵저버 패턴이다. 구조적 차이는 단 하나의 설계 결정에서 비롯된다: **옵저버 목록을 누가 소유하는가?**

|                | 옵저버                           | 이벤트 버스       |
| -------------- | ----------------------------- | ------------ |
| 옵저버 목록 소유자     | Subject 자신 (예: `UserService`) | Bus 싱글턴      |
| 생산자가 소비자를 아는가? | 암묵적으로 앎 (목록을 보유)              | 전혀 모름        |
| 소비자가 생산자를 아는가? | Subject를 직접 참조해야 함            | 전혀 모름        |
| 여러 발행 출처       | Subject마다 별도로 존재              | 하나의 Bus에서 공유 |

## 핵심 인사이트

기본 옵저버에서는 **결합이 Subject 쪽으로 이동**한다. 소비자가 세 개의 서로 다른 Subject에서 이벤트를 받아야 한다면, 각각에 직접 구독해야 한다. Subject는 옵저버 목록을 보유함으로써 여전히 옵저버들을 "알고" 있는 셈이다.

이벤트 버스는 Subject 역할을 익명의 공유 중개자로 만들어 이 문제를 해결한다. `publish(EventType, payload)`는 Subject 참조가 필요 없다. 소비자는 `subscribe(EventType)`만 호출하면 되고, 어떤 생산자가 있는지 알 필요가 없다. 양쪽 모두 **이벤트 타입 계약**만 알면 된다 — opencode에서는 `BusEvent.define()`과 Zod 스키마로 이를 강제한다.

대신 치러야 할 비용이 있다: 모든 이벤트가 하나의 버스를 공유하기 때문에 **이벤트 타입 관리가 필수**가 된다. 이것이 이벤트 버스 구현에 항상 레지스트리 패턴이 함께 등장하는 이유다.

## Push vs Pull — 두 가지 옵저버 전달 방식

opencode의 버스에서 두 방식이 모두 나타난다:

- **Push** (`subscribeCallback`): 버스가 전달을 주도하여 콜백을 호출한다. 작성하기 쉽지만, 구독자 오류가 디스패치 루프에 영향을 줄 수 있다 (opencode는 이를 막기 위해 `Effect.tryPromise`로 감싼다).
- **Pull** (`subscribe`가 `Stream` 반환): 소비자가 소비 속도를 직접 제어한다. 비동기 파이프라인에 자연스럽게 맞으며, 역압(backpressure)은 버스가 아닌 스트림 인프라가 처리한다.

## 2단계 디스패치 — 타입 필터링에 최적화된 옵저버

`wildcard` + `typed` 분리는 두 레벨에서 옵저버를 적용한 것이다:

1. **타입 채널** — 이벤트 타입마다 전용 PubSub을 가지며, 첫 구독 시 지연 생성된다. 해당 타입의 구독자만 여기서 이벤트를 받는다.
2. **와일드카드 채널** — 모든 이벤트를 받는 단일 PubSub. 와일드카드 구독자는 이벤트 타입별 추가 비용을 지불하지 않는다.

이 분리 없이는 와일드카드 구독이 있을 경우 매 `publish()`마다 모든 구독자를 타입에 상관없이 순회해야 한다 — 전체 구독자 수에 비례하는 O(N). 분리하면 타입별 디스패치는 O(해당 타입 구독자 수), 와일드카드 디스패치는 단일 채널 발행으로 끝난다.

## 근거

[[knowledge/reviews/opencode-bus]]에서 확인됨:

- `State.wildcard` (27번 줄)와 `State.typed` (28번 줄)이 2단계 구조를 구현
- `publish()` (86–107번 줄)는 타입 채널에 먼저 디스패치한 뒤 와일드카드 채널로 — 명시적인 2단계 로직
- `BusEvent.define()`은 이벤트 버스의 이벤트 계약을 명확하게 만드는 레지스트리
- `GlobalBus.emit()` (100번 줄)은 이벤트 버스가 중첩되는 방식을 보여줌: 로컬 버스 자체가 글로벌 이벤트의 옵저버
